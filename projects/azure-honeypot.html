Azure Honeypot Threat Map

A live SOC-style dashboard that maps real RDP brute-force attacks against a Windows honeypot I run in Azure. I built the whole thing end to end with Terraform.

Overview

I deployed a Windows Server 2022 virtual machine as a honeypot with Remote Desktop Protocol (RDP) deliberately exposed to the internet. Within minutes of going live, automated scanners around the world began hammering port 3389 with credential-guessing attempts. Every failed login gets captured as a Windows Security Event, enriched with geolocation data, and plotted on an interactive world map, so I can watch who is attacking, from where, and how often, as it happens.

My goal was to build a realistic, cloud-native security telemetry pipeline that collects, processes, stores, and presents attacks the way a real Security Operations Center (SOC) dashboard would.

Architecture

Attack data flows through a fully managed Azure pipeline:

Attackers → RDP (3389) → Windows VM → Security Events → Log Analytics → Logic App → Blob Storage → Static Web App

The Azure Monitor Agent, configured through Data Collection Rules, forwards failed-login Security Events from the VM into a Log Analytics workspace. An Azure Logic App runs KQL queries against that workspace to aggregate attack data daily, then writes the results to Azure Blob Storage. The frontend is plain HTML/CSS/JavaScript with Leaflet.js, hosted on Azure Static Web Apps. It reads the aggregated data to render the map, and GitHub Actions handles continuous deployment.

I defined the entire environment as Infrastructure as Code: a single terraform apply stands up the VM, networking, monitoring pipeline, and static web app.

Tech Stack

Terraform Azure Windows Server 2022 Azure Monitor Agent Log Analytics Logic Apps KQL Blob Storage Leaflet.js Azure Static Web Apps GitHub Actions

Key Engineering Details

  • Infrastructure as Code: I provision the honeypot, monitoring pipeline, and hosting entirely with Terraform, so I can rebuild or tear down the whole environment with one command.
  • Serverless data processing: an Azure Logic App runs KQL against Log Analytics to aggregate attacks daily and publish results to Blob Storage, so there are no servers to maintain for the analytics tier.
  • Interactive visualization: the Leaflet.js map uses marker clustering for high-density attack regions and shows per-attacker details (IP address, geolocation, attempt count, and targeted account names), with the data refreshing automatically.
  • Deliberately weakened target: the honeypot uses an open NSG allowing all inbound traffic, a disabled Windows Firewall, and exposed RDP. I weakened and documented all of it on purpose, since that's what makes the VM a magnet for scanners. It's a config I would never reuse in production.
  • Automated deployment: GitHub Actions redeploys the Static Web App frontend on every push.
